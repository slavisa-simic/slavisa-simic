# Sources and provenance

- The original S stays untouched at assets/source/personal-logo.png. The active header follows the current GitHub avatar, fetched from the public user API's official avatar URL. assets/profile/avatar.json records the source, MIME type, original bytes, and SHA-256. Framing preserves its image pixels.
- The latest supplied blueprint screenshot defines title/frame palette and square geometry, recorded in config/profile.json and the profile design-system override. Title assets are composed with the bundled Inter font.
- Earlier network/blueprint artwork is archived. The active carousel uses the two official logos supplied by the user for this revision, including the requested illustrated Potamorph mark.
- [Vigil README](https://github.com/slavisa-simic/vigil/blob/main/README.md), content SHA `b4f87bcf6ebe7bafffd67dcc3c0844c53f5de958`, supports the incident workflow, authentication, access control, and project technology description.
- [Tower-defense README](https://github.com/slavisa-simic/tower-defense-ai/blob/main/README.md), content SHA `a1852aab731e3e457ae8daeafb3f58a23bcbf452`, supports the prototype context, Unity/C# implementation, and the bounded briefs, Codex implementation, tooling, and validation record. See its [Built with Codex](https://github.com/slavisa-simic/tower-defense-ai#built-with-codex) section.
- The user explicitly clarified that the Potamorph showcase must focus on extensive OpenAI Codex usage and must not imply personal game-development expertise.
- [Public GitHub profile](https://github.com/slavisa-simic) supplies the verified name and LinkedIn destination. Employment, certificates, cloud expertise, email, and performance claims are not inferred.
- The official project logos are stored at `assets/profile/source/vigil-logo.png` and `potamorph-logo.png`. They are exact copies of the supplied attachments. `config/profile.json` pins their original SHA-256 hashes; `assets/profile/source/provenance.json` records their origin. The renderer only crops outer padding, resizes proportionally, and composites them. It does not recolor, regenerate, retouch, or redraw the marks.
- Actual project activity comes from GitHub's public [repository](https://docs.github.com/en/rest/repos/repos#get-a-repository) and [commit](https://docs.github.com/en/rest/commits/commits#list-commits) endpoints. `assets/profile/activity.json` records the calendar window, repository scope, per-day counts, and recent commits. These are repository counts, not an assertion of personal authorship.
- Inter is bundled from [Google Fonts' Inter directory](https://github.com/google/fonts/tree/main/ofl/inter), with its SIL Open Font License in `assets/source/fonts/Inter-OFL.txt`.
- IBM Plex Mono is bundled from [Google Fonts' IBM Plex Mono directory](https://github.com/google/fonts/tree/main/ofl/ibmplexmono), with its SIL Open Font License in `assets/source/fonts/IBMPlexMono-OFL.txt`.
- Rendering behavior was checked through [GitHub's Markdown API](https://docs.github.com/en/rest/markdown/markdown) and live GitHub styles. The preview records the rendered README and image hashes in `browser-report.json`.
- Legacy stack badges come from Shields.io's static-badge service and remain cached for historical builds. The GitHub-hosted workflow status badge stays dynamic.
- Java, PostgreSQL, Docker, and Python logos come from [Devicon](https://github.com/devicons/devicon), pinned at commit `54cfe13ac10eaa1ef817a343ab0a9437eb3c2e08` (v2.17.0). The bundled `assets/profile/icons/Devicon-LICENSE` carries its MIT attribution.
- Spring Boot, GitHub, LinkedIn, and OpenAI marks come from [Simple Icons v13.21.0](https://github.com/simple-icons/simple-icons/tree/13.21.0). `assets/profile/icons/Simple-Icons-LICENSE` contains its CC0 license. The OpenAI knot identifies the vendor of Codex; the label explicitly categorizes Codex as an AI development tool. Original paths and proportions are retained; monochrome marks use their brand color or an appropriate contrasting fill. Technology labels use bundled Inter.
- `assets/profile/icons/provenance.json` records each exact source URL and SHA-256. The SVG generator verifies cached hashes before rendering and downloads only newly configured icons. All final images are self-contained.
- The SVG image approach follows the same declarative-animation pattern used by [readme-typing-svg](https://github.com/DenverCoder1/readme-typing-svg). Our checks independently verify actual image playback, alpha, motion direction, and pixel-identical loop boundaries. [GitHub's Markdown API](https://docs.github.com/en/rest/markdown/markdown) confirms the permitted picture sources and independent link anchors survive sanitization.
